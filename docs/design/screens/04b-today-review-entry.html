Weekly review entry on Today – sketch, screen 4b

Indicative, not a pixel specification. Screen texts are Dutch, as in the app (app_nl.arb); colours follow DD-017. Why: PO feedback 01-10-2026: ⋮ → Weekoverzicht on Vandaag feels hidden. This revisits DD-018 point 4 (Today) and point 8 (start of the review). Three variants, each on the phone and on Windows. The screen keeps its current name Weekoverzicht (renaming is SPEC Q27, decided before T10.7); at the bottom, how the entry looks with the candidate names. Unchanged: the inbox line hides itself when the inbox is empty (point 4), so the review never hangs on it; Ctrl+Shift+W keeps starting the review on Windows. Today in the samples: Friday 2 October. Sample data is fictional. Orange outline = what is new.
Decided (PO, 02-10-2026): variant C, with "last completed review" as local state (not synchronised) and a device setting for when a review is due again (3–28 days, 7 by default); ⋮ on Vandaag goes, because nothing else is in it. See DESIGN.md, DD-018 points 4 and 8.

Behaviour, data and accessibility

  • Same in every variant: the review itself does not change (DD-018 point 8); Ctrl+Shift+W stays; the rail gets nothing (the review is a mode). ⋮ on Today goes, or stays with the same entry, as the PO decides; it is removed only after the new entry is built.
  • Accessibility (REQ-016): the icon has a tooltip and a semantic label "Weekoverzicht" (on Windows the tooltip adds the key); B's button and C's line have visible text; C's line reads the age in words ("laatste keer 9 dagen geleden", "nog niet gedaan"), not "9 d". All are reachable with Tab on Windows and work with TalkBack and Narrator.
  • C: "last completed review". Completed = the end screen "Klaar ✓" was reached (also when every step was empty); ending with ✕ halfway does not count. Due = never, or 7 days or longer ago; one pure function in domain/. Two ways to store it:
    • Synchronised fact (proposal): a new table weekly_reviews (UUID, completed_at, HLC, tombstone) written through ChangeLogWriter (DD-003), one row per completed review, insert-only, so two devices never conflict; "last" = the newest row. A review on the phone then also quiets the PC (after sync, M9), and the rows are a history for later (the Overview, T10.7). Schema v7 with a migration; T3.5 then becomes v8.
    • Local state: one key last_review_completed_at in local_state; no migration, but per device: after reviewing on the phone, the PC keeps saying "due".
  • T4.4 (weekly reminder, REQ-022): the reminder uses the same "due" function: on the chosen day and time it only notifies when a review is due, and the notification opens the review. If T4.4 adds a chosen weekday, "due" may become "the chosen day has passed since the last review"; that is decided with T4.4, the line follows it.
  • Windows list keys: in B and C the action row and the line are buttons above the list; ↑/↓ keep moving between cards only (as the inbox line now, DD-018 point 5).
Recommendation (variant taken; the PO chose local state instead of the synchronised fact): variant C, with the synchronised fact. The icon solves "hidden" for good, and the line turns the entry into an invitation only in the week it is due, without taking room on Today the other days. The data is a small insert-only table that fits DD-003 and gives T4.4 its rule. Cheaper fallback: C with local state (no schema step), to be moved to the table with M9. B is the most visible but costs a row every day and pushes the inbox line into a chip.
